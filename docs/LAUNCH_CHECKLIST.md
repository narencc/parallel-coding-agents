# First feedback release: what is ready and what needs people

This is a local preparation checklist. Nothing here means a post has been sent,
a site published, or a person has tried the project.

## Prepared locally

- [x] Short, evidence-first README with a precise headline.
- [x] Full beginner guide linked from the introduction.
- [x] Portable example with all five answers, drafts, original tests, and review cases.
- [x] Per-model attempts, token use, and estimated cost from the recorded run.
- [x] Free text replay with an optional paced walkthrough.
- [x] Separate sandboxed command to reproduce the evidence without API requests.
- [x] Contribution guide and specific issue templates.
- [x] Draft posts and feedback questions.
- [x] A completed second assignment with a prewritten, frozen assessment and published local evidence.

## Before sharing the first feedback release

- [ ] Review the changed files and commit the intended changes.
- [ ] Confirm which GitHub repository and visibility to use, then push deliberately.
- [ ] Open the repository as a visitor and check that the links and example are accessible.
- [ ] Invite a few people to inspect it. Start with one reader if that is easier.
- [ ] Have at least one person follow the setup instructions from a clean machine.
- [ ] Record where people get confused; improve those parts.

Do not treat our automated checks as outside-user feedback. They answer different
questions. A single reader is a useful start, not proof that everyone can use it.

## Questions for a feedback session

Ask the reader to use their own words rather than coaching them toward an answer:

1. What does this project do?
2. What did the experiment show, and what did it not show?
3. Can you find one final answer and the reason for choosing the winner?
4. Can you inspect results without a key or payment?
5. If you tried setup, where did you get stuck?

Record the date, activity attempted, confusion, and proposed improvement. Do not
invent completed feedback sessions or publish personal details without consent.

## Before a broader launch

- [ ] Resolve important feedback from the first release.
- [x] Implement and run the second assignment with tests fixed in advance.
- [x] Report its results even if they are not surprising: all five passed all 48 booking cases.
- [ ] Record a short screen demonstration if a video is useful for the chosen channel.
- [ ] Replace placeholders in the draft post with the real public link.
- [ ] Check that each claimed feature is available to visitors.
- [ ] Follow the chosen community's posting rules and publish deliberately.
- [ ] Respond to questions and acknowledge useful contributions.

A paced text replay is available now. It is not an original screen recording of
the race. Do not claim a live demo, hosted replay, or general-purpose tool exists.

## What to learn after sharing

Track stars alongside useful participation: successful reproductions, specific
questions, new test cases, contributions, and people returning for another
experiment. No star target or launch schedule is guaranteed by this plan.
